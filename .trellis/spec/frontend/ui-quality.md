# UI Quality

`shendu/public/styles.css` defines surface, ink, line, accent, radius, and shadow variables in `:root`. `applyTheme()` in `app.js` sets three accent variables and computes their text contrast. Theme settings expose six presets, custom colors, and a reduce-motion control. Shared UI must remain legible with every preset and custom accent.

The current shell has a shared top navigation and main column. Its mobile menu replaces the desktop links at narrow widths. The stage/calendar/pending-action content opens as a centered dialog from the top navigation, reusing the existing rail node. Narrow widths reflow the six overview cards, record reel, and existing forms. Check breakpoint transitions, not only wide desktop (`styles.css`).

- Preserve semantic buttons, form labels or accessible names, visible `:focus-visible`, and status feedback. `calendarHtml()`, the header menu triggers, and `openModal()` in `app.js` provide local examples.
- Dialogs use `#modal-root`; `openModal()` and the document key handler manage focus and Escape. Reuse that path for confirmation and settings dialogs.
- Keep both `@media(prefers-reduced-motion:reduce)` and the saved `reduceMotion` setting.
- The six overview category entries use local colored SVG illustrations in `assets/overview/`, with visible 日/周/月/季/年/决 marks and accessible category names. Asset provenance, source IDs and exact palette mapping live in that folder's README. Sizes are 112/96/84px at desktop/<=1280px/<=540px, derived from `--type-size`; <=1280px uses three columns. Keep each `.overview-type-card` fixed in the layout. Mouse pointer entry or keyboard-visible focus on its `.overview-type-trigger` opens `.is-expanded` and updates `aria-expanded`, scales only the internal mark to 1.14 and opens an independent `.overview-type-info` group; never increase the container width or move the other five entries. The information panel unfolds to the left at 240px wide, becomes 220px at <=1280px, and opens below with column-edge alignment at <=960px. The panel's own enter button uses shared `data-nav`; do not nest buttons or navigate immediately on the disclosure trigger. Keep one open entry. Mouse departure closes it unless keyboard-visible focus remains inside; focus departure closes it unless the pointer remains inside. A transparent hit bridge connects the icon and panel across their gap. Touch ignores pointer entry/departure and toggles on click; mouse clicks keep a hovered panel open. Escape restores focus before closing expanded states so focusin cannot reopen the dismissed panel. Use shared setOverviewType()/closeOverviewTypes(). Verify all six panel bounds and unchanged sibling geometry, including 961/1280/1281px transitions. Reduced motion must preserve immediate access to the information.
- Header branding reuses the original red `.seal` and serif `慎獨` wordmark, without rotation or theme recoloring. Top-level header links, menu/rail/account/mobile triggers have no frame, fill, capsule shadow or active dot. Current text uses its route/category color; retain separate `:focus-visible` outlines. Navigation dropdowns use `setHeaderMenu()` for a single open menu; support arrow entry/movement, Home/End, native Tab, focus-out dismissal and Escape focus restoration. The review popup has two columns but remains a disclosure of navigation buttons, not an ARIA application menu; its internal grouped surfaces may retain borders and fill. Its animation and header transitions must respect both reduced-motion settings.
- For translucent surfaces, make text, controls, focus rings, and status labels readable over all supported backgrounds and themes. Establish hierarchy with grouping, type, and spacing before effects.
- The top stage/calendar button opens the existing `#right-rail` as a centered dialog at every logged-in route, without duplicating calendar IDs or event bindings. `.right-rail.open` uses a 900px maximum width and internal scrolling; <=680px switches the stage/calendar/pending cards to one column. Its title/close header appears only in the open state; closed persistent rails on legacy wide screens keep their original layout. `setRailOverlayOpen()` controls dialog naming, main/header inert state, body scroll lock and `#rail-backdrop`, keeps Tab inside, and restores focus to `#rail-toggle` on Escape/close/backdrop dismissal. Calendar navigation closes the parent before the unsaved-change guard and route change. Existing `openModal()` child dialogs sit above the rail, make the parent inert, then restore parent interactivity and the invoking control on close. Keep backdrop/parent/child levels at 85/90/110 and clean open state before shell replacement. Verify month switching, date/record entry, stage editing, keyboard containment, close/backdrop paths and narrow/short viewports.
- The overview record reel moves continuously along a shallow U-shaped arc (sides high, center low), with card angles following the tangent. Do not substitute a straight translation with alternating card tilts. Keep the moving button's hit geometry stable: its internal `.overview-record-surface` provides the stronger hover/focus lift (-14px), scale (1.055), shadow and category border; the view action moves 6px right. Moving the button itself can lose edge hover and cause pause/resume oscillation. The visible pause control was removed by user request; only hovering an actual `.overview-record-card` pauses all cards. Use `.overview-reel-window:has(.overview-record-card:hover)`, never `.overview-reel-window:hover`: the window includes empty space below the category entries, which must keep moving. Keyboard focus exposes a static scrollable list; the saved `reduceMotion` setting and system `prefers-reduced-motion` preference disable motion and added transitions. Duplicated loop cards stay out of the accessibility and keyboard order. `bindOverviewArc()` recomputes the path on resize; `shell()` disconnects its observer before replacing the page. Loop resets and surplus record spacing stay outside the viewport. Regression-check pointer over blank window space (running), a real card including its lower edge (stable paused and raised surface), and blank space again (running).
- The daily metric-status `<select>` and date fields are intentionally native controls; their browser-owned popup geometry is acceptable in this self-hosted form. Keep their accessible names and test the opened controls at narrow widths when changing them.

`npm run check` is the existing browser-script syntax gate. The test suite covers security and backups rather than visual behavior (`shendu/package.json`, `shendu/tests/backup-security.test.mjs`). Inspect actual desktop/mobile states and exercise affected keyboard and pointer paths for UI changes.
