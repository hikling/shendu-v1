A documentation worker owns HANDOVER.md and narrowly reconciles obsolete overview behavior in DESIGN.md. A reviewer independently inspects selection/privacy/completeness and instructions after implementation. No application files under shendu/ change.

Package committed Git object bytes rather than copy the working directory. Explicitly omit temporary output/ except accepted original artwork in output/imagegen/record-library/, historical QA directories, Trellis workspace/task/runtime traces, platform-local caches and any runtime data, env/key/password/database/backup files even if accidentally tracked. Include all runtime source assets and provenance, original art/contact sheets/gallery, lockfile, frontend sources/build config, Docker inputs, tests and essential Trellis specs/workflow/helpers. Reject unsupported Git links/submodules/path traversal. Add a per-file SHA-256 manifest plus required ZIP checksum and verify both content membership and bytes before delivery. No Git history is embedded. Receivers should clone the public repository for deploy/update; ZIP supports review and local development. Packaging/verification requires Python3.11+, Git only for packaging.

Output goes to a sibling delivery directory, never live data or the tracked source. Build the final archive only after main/closure is synchronized so the embedded commit is reviewable. Docs and root tooling do not change the shendu application tree or require rebuilding its public images. Verify the existing tree release live; do not claim deployed production state.
