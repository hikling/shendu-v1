# Boundary and strategy

并行只读审查认证/记录API、备份/网络恢复、前端异步/安全，根代理负责部署脚本、依赖公告、README和发布清理。发现具体问题先给出利用/触发路径和最小复现，再分配单文件或函数所有权修复，避免多代理同时覆盖server.mjs。保留现有schema、加密及备份兼容，除非明确问题必须调整。

只在隔离临时目录做测试，不对用户运行站点做写操作。npm audit通过官方registry读取锁定依赖公告，无自动升级或force修复。构建/全量检查及必要LinuxCI验证后更新审查报告和README；不承诺绝无漏洞。

发布清理使用GitHub Releases接口或已安装CLI/浏览器可用能力，先库存再以published_at降序选择保留集合。待本次main的双架构构建/下载/健康检查完成后重新取库存，核对最新四项资产和当前应用tree标签。仅删除旧Release和其附属下载，不删除Git标签/提交；清理前后记录ID/tag/日期，避免误删新版本。无合适写接口时使用现有GitHub凭据的官方REST请求，凭据不落盘、不输出；若能力不足如实说明。
