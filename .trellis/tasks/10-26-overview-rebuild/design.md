# 概览与顶部导航设计

## 1. 边界与基线

- 基线：`codex/restore-original-ui`，起点提交 `60434e3`。现有产品代码集中在 `shendu/public/app.js`、`styles.css`、`index.html`，服务端在 `shendu/server.mjs`。
- 目标是新增一个登录后的 `overview` 视图并更换共享导航外壳。保留 `renderReview()`、`renderHistory()`、`renderActions()`、`renderBackup()`、`renderUsers()` 的页面主体与数据操作。
- 前端继续使用原生 HTML/CSS/JavaScript；本里程碑不引入构建器、框架、外部字体、统计脚本、数据库迁移或新 API。
- 首页使用已认证状态；`boot()` 完成 `refreshData()` 后进入 `overview`。现有未登录认证界面不改。

## 2. 信息架构和视觉方向

参考用户给出的 2026-10-26 示意图的四段层次：细顶部导航、居中主句、六个入口、底部横向移动内容。参考的是构图与运动关系，不使用 ClassDojo 的商标、角色、文案、图标或照片。

「慎独」的视觉意象是个人档案中的索引卡与回看长卷：主句使用有力度的中文标题字形，功能文字保持清晰的中文无衬线；六张入口卡以「日、周、月、季、年、决」为可识别的文字标识；底部轻微错位的复盘摘要卡连续移动，像翻看已经写下的记录。动感只落在这一处，其他页面保持安静。

拟定的概览局部配色：雾白背景 `#F5F7F5`、纯白卡面 `#FFFFFF`、深墨文字 `#202B31`、灰青辅助字 `#617178`、浅青灰边线 `#DCE4E2`。互动强调色沿用用户当前主题的 `--primary`，缺省为现有 `#176B67`；类别仍有文字和图形区分，不以颜色单独传达含义。该局部色板在实现阶段与现有 CSS 变量一起落入 `DESIGN.md`，避免文档与运行界面脱节。中文标题优先用系统可用的宋体类字形，正文用现有系统无衬线栈；不加载第三方远程字体。

窄屏保持顶部品牌与菜单按钮；展开后显示概览、复盘分类、历史、行动验证与账户相关入口。六张分类卡按可用宽度换列，底部卡片保持可读尺寸；横向运动限制在内容区，不让整个页面溢出。旧页面共享顶部导航，但页面主体、原有右侧阶段/日历辅助面板保持可用。

## 3. 路由与导航契约

- `state.route` 增加 `overview`，`navigate('overview')` 调用独立的 `renderOverview()`；已有 route 名和页面渲染函数不变。
- 顶部导航复用 `TYPES`、`navIcon()`、`currentActionTemplate()`、`state.user.role` 和 `attemptNavigate()`。概览六张分类卡固定使用 `TYPES` 全集；“复盘”菜单沿用 `showQuarter` 来决定是否显示 90 天入口。阶段设置开关的文案改为“在顶部复盘菜单显示 90 天入口”，设置字段和 API 不变。
- 用户菜单提供备份、账户/主题/阶段设置和授权用户的账户管理；权限判断与旧侧栏一致。原顶部栏的“阶段与日历”控制移到新顶部栏的合适位置，继续打开旧右侧辅助面板。
- 菜单是语义化按钮与可访问弹层：触发器有 `aria-expanded` 和 `aria-controls`，支持 Tab、Enter/Space、Escape、外部点击与焦点恢复；手机菜单包含同样入口。当前 route 有明确的文字与视觉状态。
- 所有会离开正在编辑复盘页的入口继续通过 `attemptNavigate()`，不绕过未保存提醒。

## 4. 记录卡数据流

```text
已认证的 GET /api/records → refreshData() → state.records
  → 过滤 status ∈ {completed, verified}
  → 每次进入概览时随机排序、取最多 12 条
  → recordSummary() 提取正文候选，截为短摘录
  → esc() 转义所有数据库文本，渲染类别/日期/标题/摘录
  → 点击卡片按 id 进入现有历史记录阅读视图
```

`GET /api/records` 已按 `user.id` 限制查询（`shendu/server.mjs:1200-1208`）；不创建公开内容接口，不把记录写入本地存储或第三方服务。筛选在浏览器内进行。未完成的 `draft` 不进入候选集。使用现有 `recordSummary()`（`shendu/public/app.js:229`）并限制显示长度；标题缺失时使用格式化周期。`verified` 已经历完成阶段，因此纳入候选。卡片的随机顺序在一次概览停留期间稳定，避免内容边移动边跳变。

有记录时，使用可循环的视觉轨道，阅读或键盘焦点落在卡片区域时可暂停；另有可见的暂停/继续控制，触屏用户也能停止运动。循环所需的复制卡不重复暴露给辅助技术。系统 `prefers-reduced-motion` 或账户 `reduceMotion` 为真时停止自动移动，并提供静态可滚动列表。没有完成记录时，展示“从每日复盘开始”的空态和可点击入口，不放虚构内容。

## 5. 兼容性、验证与回退

- 共享外壳布局从左侧栏改为顶部导航，布局 CSS 尽量局部化；旧页面主体选择器、表单渲染和服务端契约不改。检查所有旧路由、右侧辅助面板与弹窗不被新顶部栏遮挡。
- 原始 `showQuarter` 设置继续影响菜单，不影响概览卡。`shendu/public/index.html` 的 `app.js`/`styles.css` 缓存版本参数与文件修改同步更新；服务端静态资源使用长效缓存（`.trellis/spec/frontend/architecture.md`）。
- `DESIGN.md` 在实施时按已有 CSS 变量为规范值建立映射；若记录更广泛的共享行为，则建立 `UX-CONTRACT.md`，只写已验证的规范和本次实际改动。
- 验证无数据、少量数据、多类已完成记录、草稿混合数据、普通成员与管理员、阶段 90 天开关、主题预设与自定义颜色、桌面与手机、键盘菜单和两种减少动态效果。
- 无数据库迁移或新端点。若概览造成回归，可回退前端文件与缓存参数，原有记录与备份无需恢复。
- 私有新仓库由验收后的受控源码快照建立新 Git 历史；先审查纳入文件，排除 `.env`、`data/`、`tmp/`、`backups/`、密钥和本地备份。当前环境没有 `gh` CLI，发布阶段优先使用已登录的 GitHub 网页创建仓库，再通过本机 Git 推送并核实私有状态。
