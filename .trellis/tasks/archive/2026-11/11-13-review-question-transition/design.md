# Boundary and approach

Current `showDailyPrompt`/`showExtendedPrompt` synchronously switch hidden fields, heading text, art phase and side. Existing mount animations do not replay consistently. The gap belongs to their shared user-navigation presentation, not wheel event handling, record/API or CSS layout geometry.

Implement one shared, disposable transition controller, used by both daily and extended user-navigation callbacks after existing validation. Prefer a brief outgoing opacity/vertical displacement followed by incoming opacity/displacement on the mounted `.daily-editor-content` and `.daily-scene-art` (intro if included). Keep the stable canvas background/header/footer geometry and existing artwork transforms. About100ms out plus220ms in is the intended starting point; small14–18px travel. Avoid cloning React-owned forms or illustrations, whole-document screenshots, input remounts, geometry measurement or extra libraries.

Animation ownership belongs to the current canvas/account/editor and record. No global save state for visual work. Prevent overlapping navigation while the effect is running. Invalid/unchanged/programmatic redraws reveal errors synchronously; unsupported animation/reduced motion goes straight to the accepted target. Outgoing callbacks recheck ownership and saving before mutating; route replacement cancels or invalidates pending work and restores any local style/inert state. Keep input/focus semantics and no accidental final submit. In-progress editing must not be lost by a delayed collect/switch.

Expected files: new small shared transition module if warranted, app navigation entry points, scoped CSS to avoid double entrance animations, cache/check entries, behavior tests. No persistence/schema, new settings or unrelated visual redesign. Update relevant frontend spec and UX/DESIGN docs. Existing six-flow/wheel/write tests must remain meaningful; animation fallback allows non-animation tests to remain synchronous.
