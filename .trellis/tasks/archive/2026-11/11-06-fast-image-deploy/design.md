# Design

Build Linux amd64/arm64 images on native GitHub runners with BuildKit layer cache. Existing verification becomes a two-platform matrix. After both checks/smokes pass, publish compressed Docker archives and SHA-256 files as public GitHub Release assets. Use `deploy-<HEAD:shendu tree>` as immutable release identity: docs/journal-only commits reuse the same image without requiring another deployment artifact. This avoids introducing private-by-default registry packages or server registry credentials.

`prepare-image.sh` computes the tracked application tree and Docker daemon platform, verifies a local image label/platform before reuse, or downloads the exact release archive, verifies checksum, loads it and checks label/platform. It atomically publishes a managed ignored Compose override only after success. Existing .env is untouched. Refuse a user-owned/symlink override. Base Compose has a local image and never pulls an unprepared placeholder. Explicit `SHENDU_BUILD_FROM_SOURCE=1` remains available, using the same identity and override. Download failures do not silently run a build or replace running containers.

Only installers/update/image preparation/Docker/Compose/CI/tests/docs/specs change. App/UI/database/backup logic stays unchanged. Update retains optional snapshot before Git fetch; new image is prepared before up. Existing pre-change self-copied updater cannot adopt new logic mid-run; provide a latest-updater command for this transition. CI assets are checksum-bound, but checksums rely on trusted HTTPS GitHub/repository permissions; they are not an independent signing system.
