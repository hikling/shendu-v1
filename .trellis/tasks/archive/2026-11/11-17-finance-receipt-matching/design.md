# Design / ownership

- Frontend behavior change only; preserve existing server ledger/backup/update API compatibility and old entries. New expense UI requires uploaded ready receipts; income stays text-entry capable. No historical mutation, storage migration or generic finance API rejection added.
- UI implementer owns public/finance-ui.js, finance.css and tests/finance-ui.test.mjs (plus a dedicated expense view module if needed). Replace new detailed-entry surface with income-only form, no kind selector or draft consumption. Keep edit/refund entry forms compatible. Quick textarea still parses plan rows, but submit invokes upload instead of POST. Existing screenshot-only entry can remain when no text is supplied, requiring stored receipts and expense-only handling; remove manual multi-entry expense/recognition-only text bypasses from creation paths.
- Matcher implementer owns new public/finance-receipt-matching.js and its tests. Export `matchFinanceReceipts(rows,result)` where row IDs/amountCents and result receiptIds/candidates are inputs; output `{rows:[{...row,receiptIds,matchReason}],receipts:[{id,index,amounts,duplicate}],unmatchedReceiptIds}`. Only expense candidate amounts, exact positive integer cents, owned uploaded IDs present in result.receiptIds. Deduplicate candidates within an image. Auto-match only when both row amount and matching receipt are unique; duplicate input amounts or multiple matching images stay manual. One image may cover distinct unique amounts; do not do subset-sum guessing or change user values. Unknown/malformed amounts produce manual-needed; function pure and no DOM/network.
- UI maps matched rows in a dedicated finance matching dialog using existing Select/Checkbox/Input/Button. Explicit manual association supports unrecognized/ambiguous amounts; all selected entries require at least one saved image (max10). Images not used are clearly identified and require an explicit choice/acknowledgment, not silent omission. Preview is lazy, inline in same dialog with exact live/read ownership, not a replacement modal that loses matching state.
- Preserve quick-row stable IDs, manual category choices and immutable attempted payloads through partial writes/uncertain retry. Only confirmed successes remove their own physical textarea lines; screenshots stay with their matching row, never attach the entire batch to every row. Closing/canceling must not erase original plan. No request before upload/match confirmation. Reauth/replaced modal cannot be closed or overwritten by stale work.
- Root owns exact surface Select click bug investigation (finance-select CSS/z-index/pointer/focus), cache revisions, docs/spec, cross-flow review, synthetic browser validation and publishing. Receipt-client already emits per-image receiptIds on each candidate including an empty OCR fallback, so no format/storage change required.
