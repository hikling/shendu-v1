# Design and boundaries

## Ownership
Root owns shared finance-domain.js, daily-flow/schema/app daily integration, task/spec/docs, generated art and integration QA. Backend worker owns server.mjs and finance ledger persistence/backup/snapshot/API tests. Frontend worker owns finance-ui.js/finance.css and app navigation/standalone finance context, UI tests. Receipt worker owns finance-receipts.mjs, receipt-client.js, local OCR runtime/dependency/build provisioning and receipt security tests. Do not revert another owner's edits; server.mjs is backend-only, daily-flow.js/review-schema.js root-only. Agree cross-layer contracts in research/api-contract.md before integrating.

## Data
Use independent per-account encrypted finance entries/categories/day markers and soft-delete tombstones. Currency is CNY with integer cents; use the shared restricted decimal +/- parser, no eval. Entry create accepts stable client UUID for retry idempotency, updates/deletes/restore use optimistic version. Categories are per-account with archived state; archived labels remain readable. Refund references must be same-account original expenses; total refunds cannot exceed original amount, transfer excluded. All semantic mutations and fixed activity events are atomic; activity contains no monetary details or purpose.

Daily finance is an optional prompt after energy only for newly enabled daily templates; old saved snapshots lacking the feature do not gain it. New daily drafts preserve financeDraft form input (bounded primitives/receipt IDs), pending unconfirmed entry blocks advancing/locking unless confirmed or cleared. Explicit day-zero marker distinguishes unrecorded from zero; confirmed ledger entries survive deletion of review drafts. On daily completion, obtain a server-controlled day's ledger summary snapshot in the same completion transaction; discard client-supplied financeSnapshot. Locked history displays that snapshot, not current ledger. Ledger page can correct old dates independently.

## Private image flow
Browser compresses supported image inputs to readable WebP/JPEG plus small thumbnail before direct S3 upload. Original never enters HTTP API or server disk. Limit decode pixels/file bytes/count, sequential OCR/compression, cancellation and blob URL cleanup. OCR assets are pinned, bundled/self-hosted and loaded lazily with one worker; no external CDN requests or secrets in browser. Parse OCR into editable candidates; don't auto-create entries, low confidence stays visible. OCR failure allows manual entry.

Private S3 upload tickets are scoped to current account, unique random object keys, accepted variants/content types/byte lengths and short expiry. Verify signed content type/length/hash where supported, HEAD confirm uploaded object metadata before receipt ready; browser never receives secret credentials. Read URLs authorize owned ready receipts and expire. Enforce quotas and rate limits, safe HTTPS endpoints/SSRF pinning, original session after asynchronous body/network reads, no arbitrary key reads/overwrites. Metadata is encrypted and backed up; no image bytes. Config replacement cannot silently reinterpret existing object keys: pin storage identity to receipt or reject replacement while images exist. Never advertise configured storage as tested without proof. CSP adds only validated configured HTTPS storage origins for fetch/image plus same-site workers/WASM; preserve all other protections.

## UI
Finance normal route with shared header on desktop/mobile. Warm paper and bold Songti, sage/gold accents, local finance art. Month selection; income/net expense/difference; expense trend and category distribution; dated paginated entries; text/type/category filters and include-deleted recovery view. Native labeled controls enhanced through existing islands, safe escaped text. Inline create/edit form supports expression + purpose/category + note, explicit save, receipt preview/import, category management and storage setup. Loading/errors/retry/empty, per-account owner/pending/dirty guards. Daily widget uses same API/client and preserves pending draft data. No chart or image may delay ledger text or conceal literal balances as actual assets.

## Backups and rollout
Additive schema9; old personal/site backups preserve existing finance when finance section absent (unless explicit full-site replacement semantics require documented outcome), new backups validate all linked entities before mutation and include finance config/metadata under encrypted envelope. Merges use versions/timestamps/tombstones and protect deletes, fail equal-version conflicting payloads. Full-site restores re-encrypt scoped data for restored owners atomically. Account deletion cascades all finance tables. Tests use disposable fixtures only; no real S3/account credentials/data touched. Keep existing installation/publish/release model.
