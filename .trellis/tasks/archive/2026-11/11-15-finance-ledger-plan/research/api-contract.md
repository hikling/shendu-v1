# Shared integration contract

All API errors use existing {error,message}, JSON no-store, requireUser and readJson session revalidation. API prefix /api/finance; all entries and categories returned with id/version. Dates YYYY-MM-DD, month YYYY-MM, timestamps ISO, CNY cents integers.

## Shared module (root)
public/finance-domain.js exports parseMoneyExpression(text)->integer cents (signed result allowed by parser, entry amount must positive); formatFinanceMoney(cents)->Chinese locale decimal string; DEFAULT_FINANCE_CATEGORIES [{id,name,keywords,active:true}]; FINANCE_KINDS object{expense:'支出',income:'收入',refund:'退款',transfer:'不计收支'}; suggestFinanceCategory(purpose,categories,kind='expense')->id; parseReceiptText(text,{date,categories}={})->editable candidate array [{date,expression,purpose,kind,categoryId,confidence,warnings:[]}]. Built-in IDs deterministic strings e.g food,transport,shopping,housing,health,learning,entertainment,social,salary,other-income,uncategorized. Categories are independent of kind; suggestions use kind as hint. Receipt client module imports parseReceiptText.

## Ledger API (backend)
- GET /api/finance?month=YYYY-MM OR date=YYYY-MM-DD, optional q/kind/category/cursor/deleted=1 -> {entries,categories,summary:{incomeCents,expenseCents,refundCents,netExpenseCents,balanceCents,count},trend:[{date,expenseCents,incomeCents}],categoryTotals:[{categoryId,name,cents}],nextCursor,day:{date,state:'unrecorded'|'zero'|'recorded',version}?}. Summary/trend/classification cover selected date/month independent of list search filters, say so in UI. Entries newest date then stable id, page50; include deleted only requested; no truncation of aggregate.
- POST /api/finance/entries body{id:clientUUID,date,kind,expression,purpose,categoryId,note?,refundOf?,receiptIds?:[],source?:'daily'|'finance'} -> {entry,duplicate?:true}. Amount recomputed server-side from expression; <=2 decimals, positive. Same client UUID+exact normalized payload replay idempotent; different payload409.
- PUT /api/finance/entries/:id same fields+version ->{entry}; DELETE same path body{version} ->{entry} soft-delete; POST /:id/restore {version}->{entry}. Unknown/foreign404, stale409, soft-deleted cannot edit.
- POST /api/finance/categories {id:clientUUID,name,keywords:[]} ->{category}; PUT /categories/:id {version,name,keywords,active} ->{category}. Fixed base IDs accepted for reads, saved custom IDs UUID. Cap categories and keyword counts; archive not harddelete.
- POST /api/finance/day {date,state:'zero'|'unrecorded'} ->{day}; cannot zero while active net entries inconsistent. Data is per-user date, independent of review lifecycle.
- Ledger entry output {id,date,kind,expression,amountCents,purpose,categoryId,note,refundOf,receiptIds,source,version,createdAt,updatedAt,deletedAt}. Refund only against same-account expense, caps under transaction.

## Receipt service module (receipt worker, backend integrates)
finance-receipts.mjs exports createFinanceReceipts({db,setting,putSetting,encryptData,decryptData,dataScope,now,readJson,json,error,assertPublicHttps,s3Request,normalizeBackupConfig,sessionUser,withActivity,recordActivity}): {handle(req,res,url,user):Promise<boolean>, exportUser(userId),validateImport(data,validUserIds?),importUser(userId,data,{replace}), ...}. Constructor can create additive tables; coordinate backup hooks with backend worker directly. Do not edit server.mjs. Returned handle true iff route handled.
- GET /api/finance/storage ->{configured,config:{endpoint,region,bucket,directory,pathStyle,accessKey},version,targets:[{id,name}]}; never secret. PUT samepath {config,version?,reuseTargetId?} ->safe result. Existing secret stays only if intentionally omitted. Reuse actual owned backup target via injected helper backend supplies; no foreign target IDs. Validate config before save.
- POST /api/finance/receipts/prepare {id:clientUUID,hash:SHA256,variants:{image:{bytes,type:'image/webp'|'image/jpeg',sha256},thumb:{bytes,type,sha256}}} ->{receiptId,uploads:{image:{url,headers},thumb:{url,headers}},duplicate?:true}; scoped private presigned PUT. If ready exact hash owned ->ready duplicate may return no uploads.
- POST /api/finance/receipts/:id/complete ->{receipt:{id,hash,ready:true}}; HEAD validate both variants before ready, session recheck. POST /api/finance/receipts/read {ids:[...],variant:'thumb'|'image'} ->{urls:{[id]:signedURL}}. Only owned ready.
- Backend entry validation verifies each receipt ID owned+ready. Soft-delete entries does not delete receipt automatically; recovery works. Receipt service receipt export/import includes storage association/config; pin/reject config replacement so old images don't disappear.

## Browser receipt client (receipt worker)
public/receipt-client.js exports processReceiptFiles(files,{request,isCurrent=()=>true,onProgress=()=>{},signal,categories,date,upload=true}={})->Promise<{candidates,receiptIds,warnings}>, loadReceiptUrls(ids,variant,{request,isCurrent})->Promise<urlMap>, disposeReceiptWorker(). It sequentially decodes/limits/compresses selected images, local OCR, preview candidates, optionally uploads compressed variants only after explicit user action. No storage configured: show warning, still OCR/manual candidates, no false stored receipt IDs. Each candidate may carry receiptIds. Lazy local OCR imports bundled assets. Own package.json/package-lock/build provisioning and asset path policy; root will merge syntax check entries only after coordination.

## Browser finance UI (frontend worker)

Module-local write pending and exact account/connected form guards. beginWrite/endWrite bridge state.saving owner without clearing another writer. Daily draft {expression,purpose,categoryId,note,receiptIds:[]} supplied by reference and onDraftChange; all edits persist this bounded object into state.current.data.financeDraft (root). Explicit confirmation clears that draft but never clears unrelated review dirty. page no global arbitrary inline scripts. Only daily readonly snapshot data renders without API reads/mutation. Shared module may use receipt-client dynamically; no real credentials needed.

Frontend worker owns app.js navbar/mobile/navigate finance route and helper financeUiOptions if needed, but do NOT touch daily templates/bindReview/collectCurrent or shared review-schema.js/daily-flow.js (root). Expose function financeUiOptions(container,extra={}) for root daily: wraps request/renderMarkup/global modal/owner callbacks and passes captured stable account ID and connected surface; cancel any page controller on shell/re-auth safely. Coordinate app insertion locations with root.

## Daily data (root/backend)
review template daily.financeEnabled true default for new settings/new records, missing in existing saved template snapshots means false; backend preserves and normalizes this distinction. dailyPrompts(...template) includes finance iff financeEnabled===true. New defaults and missing current legacy settings normalize true; historical snapshots normalize missing false. Root new daily record template snapshot has enabled true; existing saved ones without flag stay old. data.financeDraft bounded primitives only; has nonempty draft blocks finance prompt next/finalcomplete until confirm or clear. data.financeSnapshot is server-controlled only on daily completion, {date,state,incomeCents,expenseCents,refundCents,netExpenseCents,count,entries:[{id,kind,amountCents,purpose,categoryName}],capturedAt}; current live balance not silently substituted. Root initial mount of widget accepts snapshot if readonly. Do not add step to other five flows.
