# 公开仓库与部署文档更新

## Goal

把 `hikling/shendu-v1` 作为可以公开查看、按文档实际搭建的当前项目发布。README 首屏应介绍新版概览与顶部导航；安装、更新与恢复说明应指向新仓库及真实配置。

## Requirements

- 将 `hikling/shendu-v1` 从 Private 改为 Public，确认默认分支仍为 `main`，原 `hikling/Shendu` 不受影响。
- 发布前检查当前仓库所有提交的文件名与关键文档，不公开 `.env`、数据库、内部主密钥或备份。
- 重写 README：准确概述当前功能；给出 Debian 12/13 的全新安装（DNS、80/443、克隆、安装、域名配置、启动、健康检查）、本地开发、更新、数据与密钥位置、故障排查。
- 文档里的仓库 URL、路径和脚本命令统一以 `shendu-v1` 为准；升级文档保留已有数据迁移及回退说明，但与新路径一致。
- 修正 `PRODUCT.md` 对“私有仓库”的旧陈述和过时任务路径。不改应用业务逻辑、配置格式或部署脚本，除非验证证明确有搭建阻断。
- 把新仓库的版本元数据与静态资源缓存参数从继承的旧版本统一到 `1.0.0`；本地 Node 最低版本与免启动参数的 SQLite 支持保持一致。
- 添加 Linux 构建检查，验证 Compose 配置、Docker 镜像与容器健康接口，作为本机无 Docker 时的可重复构建证据。

## Acceptance Criteria

- [x] README 不再声称旧 `code.html` 视觉稿、左侧抽屉或原 `Shendu` 仓库是当前版本；新仓库链接和所有复制命令一致。
- [x] README 的 Docker Compose、环境变量、Caddy、健康检查与现有文件匹配；有明确的首次运行验证及保留数据说明。
- [x] `shendu/VERSION`、`package.json`、`index.html` 的版本一致，Node 最低版本可直接运行当前启动命令。
- [x] 在可用环境中通过文档/脚本静态检查和隔离的启动烟测；若本机缺 Docker，明确记录无法本地执行容器部署。
- [x] 远程 Linux 构建检查通过：Compose 可解析、镜像可构建、容器 `/healthz` 可响应。
- [x] 新仓库公开且 `main` 能读到更新后的 README；远端可见性、提交和文件内容读回确认。
- [x] 仓库历史未含运行密钥、数据库或备份；原仓库仍保留。

## Out of scope

- UI 再设计、记录业务规则和后端接口修改。
- 操作用户的生产服务器、迁移真实数据库或替用户设置域名 DNS。
