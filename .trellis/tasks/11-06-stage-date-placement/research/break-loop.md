# 阶段日期错位：重复修复分析

## 1. 根因分类与已知边界

- D（验收覆盖缺口）：日期总数、唯一性和 DOM 正确，不能证明日期画在正确星期/周行。旧版强制隐藏月外占位后仍有30个唯一日期、一个“1”，但1日从周日移到周一。
- E（隐含布局假设）：原生 table 节点混合 Grid 行，日期依赖空白格的隐式占位。本次消除这两种依赖。
- 用户实际截图出现两个“1／廿三”。Chrome156/Edge156的普通基线没有复现该重复绘制，不能认定上述注入是用户真实触发条件。

## 2. 前两次修复为什么不足

1. 分离 day/button class 阻止按钮继承格子属性，但保留原生表格布局路径。
2. 将原生 table/tr/td 改为 block/Grid 仍依赖空白格占位；原生表格元素也仍能受其他表格样式影响。
3. 旧验收重视节点数量和普通截图，没有断言每一天的真实横坐标/纵坐标。线上下载资源为 stagegrid1，没有证据支持简单归因旧缓存。

## 3. 预防机制

| 优先级 | 机制 | 落实 |
|---|---|---|
| P0 | 结构 | 仅阶段页使用 DayPicker 提供的稳定 div 槽，保留完整 ARIA 和组件焦点所有权，移除原生表格子树 |
| P0 | 定位 | 每格按真实本地公历星期显式指定列，空周保留正高度 |
| P0 | 回归 | 每日期实际中心对齐独立算出的星期列/周行；真正在运行的隐藏占位注入；全月/跨年/闰年、空数据和返回焦点 |
| P1 | 环境 | 对照公开线上资源；独立 Chrome 页面缩放与 CSS zoom 分开记录 |
| P1 | 审查 | 明确已复现故障、未复现用户绘制、隔离环境与线上账户的证据边界 |

## 4. 系统性扩展

共享验证日历仍用原始 shadcn/DayPicker table，未套用阶段 Grid 或修改验证策略。测试同时保留其6周、月切换、禁用、选择及焦点契约。本任务不重画已确认的页头、统计和其他页面。
